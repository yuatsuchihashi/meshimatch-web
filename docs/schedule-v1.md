# 日程調整 v1

2026年11月25日。ユーザーの指示で、エリア調整・店舗リンク共有より先に日程調整を実装する。
LINEの日程調整の「候補作成 → ○・△・×で回答 → 一覧で比較」を参考にする。
公式の参照先は https://guide.line.me/ja/communication/schedule.html 。

## 試せる流れ

1. `/instant` で日程と集合エリアの状況を選ぶ。日程が「みんなで調整」なら「日程の候補を作る」から進む。
2. 幹事を含む人数とタイムゾーンを設定する。集まりの名前は任意。空欄の場合は「みんなの日程調整」として作成する。
3. カレンダーで複数の日付を選び、各日の朝・昼・午後・夜を複数選択する。「朝から夜まですべて選ぶ」で4枠をまとめて追加できる。日程作成と候補追加の両方で共通。ドロップダウンは使わない。
   「時間はあとで」と任意の開始・終了時刻も同じ画面で選べる。既存の候補の時間帯は保持する。
   朝・昼・夜にはLucide公式からダウンロードした線画SVGを使用する。取得元とライセンスは `public/icons/schedule/README.md` と `LICENSE` に保存する。
4. 必要なときだけ開始・終了時刻を入力する。30分区切りのグリッドを使わず、任意の分まで指定できる。
5. 作成後の共有リンクをコピーする。リンクを知っている人はログインせず回答できる。
6. 名前を入力し、全候補へ○・△・×で回答する。補足は任意で、参加者に公開される。
7. 候補ごとの集計と日程×参加者の回答一覧を見る。自分の回答は保存したブラウザから編集できる。
8. 全員の○がそろった候補を、作成したブラウザの幹事が確認して決定する。
9. 日程と場所を調整する場合、幹事は日程作成直後に「場所調整に進む」から場所アンケートを作成できる。その後は全員が同じ日程ページから場所アンケートにも回答できる。
10. `/instant?schedule=…` に日程と参加人数を引き継ぐ。最初に集合エリアが決まっていた場合は指定エリアでのお店選び、未定の場合はエリア調整へ進む。

## 判定と変更

- 参加人数は既存のお店選びと同じ2〜8人、候補は1〜30件。幹事自身も回答する。
- ○は参加可能、△は条件付き、×は難しい。△と未回答を○に含めない。
- 未回答が残る候補は確定できない。参加が難しい人がいる候補を多数決で自動確定しない。
- ランチ・午後・夜は大まかな時間帯。集合時刻や滞在時間の一致を自動判定したとは扱わない。
- △の条件は補足で相談してもらい、合意できたら本人が○へ変更する。
- 合う日がなければ幹事が候補を追加できる。以前の回答を残し、新しい候補だけ全員未回答になる。
- 決定後は回答を固定する。幹事が再開してから変更できる。
- 自動更新は一覧表示中に10秒ごとと画面への復帰時。回答の途中では入力内容を上書きしない。

## 保存と実装範囲

- 実装は `meshimatch-web` のNext.js本体。単独HTMLではない。
- サーバーは `.localdb/schedules/<id>.json` に保存する。サーバーを再起動しても残る。データはGitに含めない。
- 回答の編集キーと幹事キーをブラウザへ保存する。公開APIではこれらを返さず、サーバーはハッシュだけ保存する。
- 同じ名前でも他人の回答を上書きできない。同じ回答IDでの再送は追加票にならない。
- 同じ端末で複数人が試せる入口もある。
- ローカルモードだけで利用できる。外部公開・本番DB・LINE連携・通知・アカウント復元は今回の対象に含めない。
- `127.0.0.1` のリンクは同じPCに向く。別端末の友人に送るには、後で共有可能なサーバーへ公開する必要がある。
- 人数で回答の完了を管理する試作。招待者の名簿による本人確認は行っていない。
- お店選びに渡すのは日程の表示と参加人数。未来日の営業時間や空席を検証する機能は未実装。
- エリア調整は11月26日に追加（`docs/area-poll-v1.md`）。店舗リンク共有、写真中心の候補一覧の仕上げは引き続き未実装。

## ローカル起動

```bash
MESHIMATCH_LOCAL_MODE=1 NEXT_PUBLIC_MESHIMATCH_LOCAL_MODE=1 NEXT_DIST_DIR=.next-build npm run build
MESHIMATCH_LOCAL_MODE=1 NEXT_PUBLIC_MESHIMATCH_LOCAL_MODE=1 NEXT_DIST_DIR=.next-build npm run start -- --hostname 127.0.0.1 --port 4317
```

入口は http://127.0.0.1:4317/schedule 。

## 確認したこと

- 日程調整と既存機能を含むVitest 178件、Nodeテスト3件。
- TypeScriptを含むNext.js本番ビルド、新規日程調整ファイルのESLint。
- ブラウザで作成、○・△・×の保存、複数人の回答、回答の変更、条件付きの候補を確定できないことを確認。
- 既存回答を残した候補追加と、その候補の未回答表示を確認。18:17〜20:09のような30分単位以外の入力も保存できた。
- 日程決定から既存のお店選びへの遷移を確認。
- 狭い画面とPC幅の表示を確認。
- 既存の `DiscoveryFlow.tsx` 全体のESLintには、今回の変更前からある同期的な状態更新を伴う `useEffect` 2箇所のエラーが残る。日程調整の新規ファイルのESLintは通過。既存フローの状態管理の改修は今回行っていない。
