## 再現に使った例

- 日程と場所が未定の2人。幹事がChromeで日程・場所を準備。別ブラウザの参加者が日程に○で回答し、続いて出発を新宿、解散後を未定として回答した。
- 東京から来て大宮へ向かう人と、浅草を往復する人。サンプル上の上野は前者にとって行き16分・解散後34分。「最大＋16分」は後者の遠回りを表す。個人の時間は本人の端末で表示し、グループの差の説明は展開して読めるようにした。
- 残りの検証課題は、初めて使う人がヒントなしで自分の回答を終えられるか、幹事が候補を比較して一つ選べるか。今回はローカル環境と架空の経路・店舗を使用した。

## 場所とお店の希望を続けて回答する

幹事は「集まりを作る」で日程、集合エリア、お店の調整が必要かを選ぶ。お店には「決まっている」「みんなで調整」「調整しない」の3通りがある。「調整しない」はお店が未定でも選べる。日程とエリアが決まっていて調整する項目がなければ、そのままホームに戻れる。

お店だけを調整する場合、幹事は集合エリア・人数・レストランかカフェかを指定して、お店のアンケートを作成する。幹事は自分の回答を入れる前に招待リンクをコピーできる。参加者は好きなタイミングでそのリンクを開き、名前と希望を回答する。リンクを開いただけでは回答人数に含めない。幹事も参加人数のうちの1人として回答する。

日程が決まっていて場所とお店を調整する場合は、各自の端末で招待リンクを開き、場所の回答からそのままカフェまたはレストランの希望へ進む。日程も調整するときは、最初に日程を答える。店舗候補を計算するのは日程・集合エリアが確定し、参加する人の希望がそろった時点。7人に送って確定日に○の人が5人なら、その5人の希望を使う。幹事も参加する日は同じアンケートに答える。

| 場面 | 画面の動き |
|---|---|
| 自分の希望を答える | 場所を送信すると、同じ端末で食事用またはカフェ用のアンケートが開く。エリア未定の間、食事ジャンルは候補エリア全体から選べる。個別の希望や予算は本人の編集画面で確認する |
| お店を比較する | 全員の回答がそろうと、それぞれが予算と食事条件内で注文できる店から最大3店を表示。写真・メニュー例・価格を比較できる。該当店がゼロの場合は、その理由と自分の回答への戻り口を表示する |
| おすすめのお店がある | 参加者からの紹介を結果画面にも載せる。サンプルDBで店名が一意に一致し、全員の条件を満たした店は候補に入ることがある。共有された外部リンクの内容は自動判定しない |
| お店が決まる | 幹事が1店を選ぶと同じ集まりに結果が表示される。幹事は選び直せる。日程や場所を決め直した場合は、その条件で希望を集め直す |
| 後で戻る | ホームには、そのブラウザで作成・回答した集まりと、次にできる操作を表示。プロフィールで保存した表示名が、新しい集まりで最初に回答する人の名前の初期値になる |

店舗・価格・メニュー・評価は試作用データで、写真はイメージ。決定した日時の実際の営業、空席、予約は確認しない。幹事は共有前に場所からお店までプレビューできる。プレビューの操作は参加者の回答に含めない。ローカル版の共有リンクは同じPC上で試せる。

ブラウザでは2人のカフェ会で、プロフィールの表示名が日程の回答欄に入るところから確認した。参加者が日程に○、場所に「どこでも大丈夫」と回答すると、その集まりがホームに載った。幹事が日程・丸の内を確定した後、同じブラウザで「お店で決めたい」「評判のよさ」「予算1,500円」と答えると、写真付きの3候補が表示された。別の7人の食事会では○の5人だけが対象となり、4人まで回答した状態で候補が公開されないこと、5人目の回答・幹事の決定・選び直しを確認した。

11月28日の確認では、日程が決まっていてエリアが未定のカフェ会を作った。2人目として招待リンクを開き、「どこでも大丈夫」からカフェの質問へ進み、「スイーツ」「評判のよさ」「予算2,000円」を送信。画面に「2 / 2人がカフェの希望を回答」と表示された。幹事が新宿を確定すると、同じ参加者画面で再回答せずに「庭先のティールーム」など3候補が表示された。
